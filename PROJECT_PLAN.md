# FasterInvoiceEscrow

## One-Line Summary

FasterInvoiceEscrow is a USDC-native B2B invoice escrow demo on Arc Testnet. A merchant creates an invoice, a payer funds it, a reviewer confirms delivery, and the escrow contract releases or refunds the payment according to the invoice state.

## Product Thesis

Arc's USDC gas model is a natural fit for business payment workflows because users can reason about fees and invoice amounts in dollar-denominated units. FasterInvoiceEscrow demonstrates a compact version of that workflow:

- A merchant creates a structured invoice.
- A payer funds the invoice with USDC.
- A reviewer confirms delivery.
- Funds are released to the merchant or refunded to the payer.
- Disputed invoices can be resolved by a configured resolver.

The demo is intentionally narrow: it is a testnet application for exploring Arc's EVM compatibility, USDC ERC-20 interface, wallet UX, contract verification, and static frontend deployment.

## User Roles

- Owner/admin:
  - Deploys the contract.
  - Sets or rotates the default resolver.
- Merchant:
  - Creates invoices and receives released USDC.
- Payer:
  - Reviews an invoice and funds it with Arc Testnet USDC.
- Reviewer:
  - Approves delivery before release. In the MVP this can be the payer, or a separate reviewer wallet set when the invoice is created.
- Resolver:
  - Resolves disputed invoices by releasing funds to the merchant or refunding the payer.

## User Flows

1. Create invoice:
   - Merchant connects wallet.
   - Merchant enters payer address, reviewer address, amount, due date, short title, metadata URI/hash, and terms hash.
   - Frontend calls `createInvoice`.
   - Contract emits `InvoiceCreated`.
   - UI shows invoice ID and ArcScan transaction link.
2. Fund invoice:
   - Payer connects wallet on Arc Testnet.
   - UI checks USDC balance and allowance for the escrow contract.
   - Payer approves USDC if needed.
   - Payer calls `fundInvoice`.
   - Contract transfers USDC into escrow and emits `InvoiceFunded`.
3. Approve and release:
   - Reviewer calls `approveDelivery`.
   - Payer calls `releaseInvoice`.
   - Contract transfers USDC to merchant and emits `InvoiceReleased`.
4. Cancel before funding:
   - Merchant or payer cancels an unfunded invoice.
   - Contract emits `InvoiceCancelled`.
5. Dispute:
   - Payer or merchant calls `openDispute` with a `reasonHash`.
   - Contract emits `InvoiceDisputed`.
   - Resolver calls `resolveDispute(invoiceId, Resolution.Release)` or `resolveDispute(invoiceId, Resolution.Refund)`.
   - Contract emits `DisputeResolved` plus `InvoiceReleased` or `InvoiceRefunded`.
6. Refund:
   - If a dispute is resolved in favor of the payer, the contract transfers escrowed USDC back to the payer and emits `InvoiceRefunded`.

## Smart Contracts

### FasterInvoiceEscrow

- Purpose:
  - Store invoice records and hold USDC escrow balances for funded invoices.
  - Provide a simple state machine for business payment settlement on Arc Testnet.
- External token:
  - `IERC20 public immutable usdc`
  - For Arc Testnet deployment, use `0x3600000000000000000000000000000000000000`.
  - For local tests, deploy `MockUSDC` with 6 decimals.
- Enums:
  - `InvoiceStatus`: `None`, `Created`, `Funded`, `Approved`, `Disputed`, `Released`, `Refunded`, `Cancelled`
  - `Resolution`: `Release`, `Refund`
- State:
  - `uint256 public nextInvoiceId`
  - `address public owner`
  - `address public defaultResolver`
  - `mapping(uint256 => Invoice) public invoices`
  - Aggregate counters: `totalCreated`, `totalFunded`, `totalReleased`, `totalRefunded`, `totalDisputed`
- Struct:
  - `uint256 id`
  - `address merchant`
  - `address payer`
  - `address reviewer`
  - `address resolver`
  - `uint256 amount`
  - `uint64 createdAt`
  - `uint64 dueAt`
  - `InvoiceStatus status`
  - `string metadataURI`
  - `bytes32 termsHash`
  - `bytes32 disputeReasonHash`
- Functions:
  - `constructor(address usdc_, address defaultResolver_)`
  - `createInvoice(address payer, address reviewer, address resolver, uint256 amount, uint64 dueAt, string calldata metadataURI, bytes32 termsHash) returns (uint256 invoiceId)`
  - `fundInvoice(uint256 invoiceId)`
  - `approveDelivery(uint256 invoiceId)`
  - `releaseInvoice(uint256 invoiceId)`
  - `cancelInvoice(uint256 invoiceId)`
  - `openDispute(uint256 invoiceId, bytes32 reasonHash)`
  - `resolveDispute(uint256 invoiceId, Resolution resolution)`
  - `setDefaultResolver(address newResolver)`
  - `getInvoice(uint256 invoiceId) external view returns (Invoice memory)`
  - `listInvoiceIds(uint256 startId, uint256 limit) external view returns (uint256[] memory)`
- Events:
  - `InvoiceCreated(uint256 indexed invoiceId, address indexed merchant, address indexed payer, address reviewer, address resolver, uint256 amount, uint64 dueAt, string metadataURI, bytes32 termsHash)`
  - `InvoiceFunded(uint256 indexed invoiceId, address indexed payer, uint256 amount)`
  - `DeliveryApproved(uint256 indexed invoiceId, address indexed reviewer)`
  - `InvoiceReleased(uint256 indexed invoiceId, address indexed merchant, uint256 amount)`
  - `InvoiceRefunded(uint256 indexed invoiceId, address indexed payer, uint256 amount)`
  - `InvoiceCancelled(uint256 indexed invoiceId, address indexed cancelledBy)`
  - `InvoiceDisputed(uint256 indexed invoiceId, address indexed openedBy, bytes32 reasonHash)`
  - `DisputeResolved(uint256 indexed invoiceId, address indexed resolver, Resolution resolution)`
  - `DefaultResolverUpdated(address indexed oldResolver, address indexed newResolver)`
- Access control:
  - `createInvoice`: any merchant wallet.
  - `fundInvoice`: invoice payer only.
  - `approveDelivery`: invoice reviewer, or payer if reviewer is `address(0)`.
  - `releaseInvoice`: payer only after the invoice is approved.
  - `cancelInvoice`: merchant or payer only while status is `Created`.
  - `openDispute`: merchant or payer only while status is `Funded` or `Approved`.
  - `resolveDispute`: invoice resolver or default resolver only while status is `Disputed`.
  - `setDefaultResolver`: owner only.
- Failure cases:
  - Zero addresses for payer, merchant, or USDC.
  - Zero amount.
  - Funding by non-payer.
  - Funding an invoice that is not `Created`.
  - Insufficient allowance or balance.
  - Release before approval.
  - Dispute or resolution in the wrong state.
  - Refund or release transfer failure.

## Frontend

- Dashboard:
  - Shows connected wallet, Arc network status, contract address, USDC balance, total invoices, funded amount, released amount, refunded amount, disputed count, and quick links.
- Create Invoice:
  - Inputs: payer, reviewer, resolver optional, amount in USDC, due date, title, metadata URI/hash, terms hash.

  - Reads recent invoice IDs from contract state.
  - Filters by status.

  - Shows full invoice data, lifecycle status, role addresses, amount, metadata, and transaction links.
  - Actions: approve USDC, fund, approve delivery, release, cancel, open dispute, resolve release, resolve refund.
- Technical Notes:
  - Static page or Markdown link for Arc-specific integration notes.

### Wallet and Network UX

- Required wallet:
  - MetaMask, Rabby, Coinbase Wallet, or another EVM wallet that can connect to Arc Testnet.
- Network switching:
  - Use EIP-3085 `wallet_addEthereumChain` with:
    - `chainId`: `0x4cf172`
    - `chainName`: `Arc Testnet`
    - `nativeCurrency`: `{ name: "USDC", symbol: "USDC", decimals: 18 }`
    - `rpcUrls`: `["https://rpc.testnet.arc.network"]`
    - `blockExplorerUrls`: `["https://testnet.arcscan.app"]`
  - Warn that some wallets may display the gas asset as ETH even though Arc uses USDC.
- Explorer links:
  - Transaction: `https://testnet.arcscan.app/tx/<hash>`
  - Address: `https://testnet.arcscan.app/address/<address>`
  - Contract: `https://testnet.arcscan.app/address/<contractAddress>`
- Error states:
  - Wrong network.
  - Missing deployment address.
  - Insufficient Testnet USDC for gas or invoice amount.
  - Missing allowance.
  - Rejected wallet signature.
  - Contract revert with a friendly message.
  - RPC unavailable.

## Risks and Guardrails

- Risk: Confusing Arc native USDC gas decimals with the USDC ERC-20 interface decimals.
  - Guardrail: Use `parseUnits(amount, 6)` for invoice token transfers and reserve 18-decimal native currency handling only for wallet network metadata.
- Risk: Treating testnet funds or records as durable assets.
  - Guardrail: Include Arc Terms references and disclaimers that Testnet USDC has no monetary value.
- Risk: Overbuilding a backend before the core dApp works.
  - Guardrail: Keep MVP as static frontend plus smart contract backend.
- Risk: Publicly sharing private business data.
  - Guardrail: Use fictional demo metadata and hashes only.
- Risk: Deploying to mainnet or using real funds by mistake.
  - Guardrail: Hard-code Arc Testnet defaults in docs and require explicit config for any other network.
